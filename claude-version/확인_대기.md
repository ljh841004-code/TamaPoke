# 확인 대기 (사용자 테스트 중)

## ko11.5 — 데이터가 쌓인 뒤의 동작 (2026-09-27)
- 상황: 세이브 데이터 때문으로 보이는 부팅 반복(USB 연결/끊김, 화면 안 켜짐) → 0x0 전체 설치로 초기화 후 복구.
  ko11.5에서 빠른 연타 렉은 **현재 없음** (새 게임 상태).
- 사용자가 새 게임으로 데이터를 쌓아 가며 확인 중. 결과를 알려 주면 이어서 대응.
- 확인할 것
  - 훈련(공격·공놀이) 빠른 연타 렉: 결과 화면 "그리기 최대 / 멈춤 최대" 숫자
  - 부팅 반복이 다시 생기는지. 생기면 화면의 `last stop: N 단계` + 원인(CRASH/BROWNOUT) 사진을 받기
    - save:* 단계면 세이브 읽기 쪽 (pet/box/hall/fame/dex) 추가 검사
    - first frame / running 이면 첫 화면 그리기 (스프라이트·박스 데이터)
  - 보관함·명예의 전당·도감이 많이 찼을 때(NVS 용량) 저장/부팅
- 이후 정리: 원인이 좁혀지면 결과 화면의 측정 표시는 뺄 것

## 부팅 반복 원인 (해결)
- 조립할 때 PWR 버튼이 계속 눌린 상태였음 → 전원 칩이 4초 길게 누름으로 보고 전원을 끔 → 재부팅 반복.
  펌웨어·세이브 문제가 아니었음 (세이브 초기화는 결과적으로 불필요했음)

## 다음 펌(ko11.6)에 들어갈 것 (아직 빌드 안 함)
- 메뉴 터치가 가끔 한 번에 안 먹던 문제: 터치 시간을 "처리한 시각"이 아니라 "읽은 시각"으로 잼
  (render ~70ms 동안 쌓인 누름+뗌이 한꺼번에 처리되면 0ms로 계산돼 스침(<60ms)으로 버려졌음)
- 시간 설정·네트워크 화면: 위쪽 빈 곳 두 번 탭 = 나가기 (위쪽 작은 ▲ + 아래 안내 글). 네트워크는 전에 "위쪽 한 번 탭"
- 공간 정리 (파티션): FAT 9MB(안 씀) → 앱 6MB×2 + nvs2 256KB. nvs(0x9000)·otadata(0xe000)는 그대로 → 세이브 유지
  - 보관함·왕관·명예의 전당·도감 기록은 nvs2로 옮김 (첫 부팅 때 한 번 복사, 성공해야 옛 자리 삭제)
  - 설치: **3개 파일**(0x0 부트로더 / 0x8000 새 파티션 / 0xe000 앱)로 해야 새 배치가 적용됨.
    앱 파일만(0xe000·SD 업데이트) 올리면 옛 배치 그대로 동작 (문제 없음, 공간만 안 늘어남)
  - 빌드: sketch의 partitions.csv + `--build-property upload.maximum_size=6291456`, 결과는 $S/out7
  - 앱이 3MB를 넘기 시작하면 옛 배치 기기는 SD 업데이트 불가(Update.begin이 거부) → 그 전에 3개 파일 설치 필요
- SD 세이브 백업: /tpsave/save0.bak, save1.bak 번갈아 (CRC, 쓰고 나서 다시 읽어 확인). WiFi(tpnet)는 제외
  - 자동: 하루 1번 + 종 바뀜(부화·진화·새 파트너) + 챔피언 + 작별. 부팅 1분 뒤부터, 훈련·전투·화면 꺼짐 중엔 안 함
  - 수동: 네트워크 > [세이브 백업] → [지금 백업] / 백업 눌러 복원(확인 창)
  - 부팅 때 새 게임(스타터 선택) + SD 백업 있으면 "복원 / 새로 시작" 질문
